# Offline native glTF compression builder candidate

This independent namespace builds complete pinned Draco 1.5.7 and meshoptimizer 1.1 static PIC libraries, then links the real Blender `common.cpp`, `encoder.cpp` and `decoder.cpp` wrappers into `libbf_intern_draco_bridge.so` and `libbf_intern_meshopt_bridge.so`. It installs native CMake/pkg-config metadata, original notices, sealed addon Python sources, and host/HAP DLL namespace copies. Source-only preparation and a read-only native tool/preprocessor plan are the only stages run when this candidate is frozen. Native full, actual bpy compressed glTF and HAP acceptance are separate gates.

The complete original archives live as ordinary Git parts, each at most 32 MiB, in `tpr/sources/draco-1.5.7` and `tpr/sources/meshoptimizer-1.1`. Reconstruction verifies every part plus the exact original size/SHA. ZIP validation rejects noncanonical paths, duplicate/case-colliding prefixes, mismatched types, symlink/special/encrypted members, wrong roots and oversized archives before writing. Full inventories verify pristine complete extraction. The two tiny standalone wrapper header patches apply only to a copied source tree; before/after SHA and full forward/reverse proof are sealed. The optional addon cleanup patch stays unapplied.

The inspected feature matrix is recorded in `feature-matrix.json`: Draco mesh/pointcloud, encoder/decoder, normal encoding, standard/predictive edgebreaker and backwards compatibility retain Blender/upstream defaults. The baseline does not enable restricted GLTF-bitstream, transcoder or Googletest. Eigen, gulrak/filesystem, TinyGLTF and Googletest optional submodule content is not promised by the original GitHub ZIP; no fetch or unpinned download occurs. Enabling such a different feature matrix requires new complete pinned entries and a new lock. The portable change is static PIC upstream linkage into the actual shared Blender wrappers, preserving codec behavior.

Every output root must be absent under private XDG_CACHE_HOME. Prefixes must stay inside that root and outside reserved builder paths. Exact owned roots may resume with `--resume`; changed locks/prefixes/TMPDIR, parent traversal, output symlinks/special nodes and existing unowned roots are rejected. Sources reject all links. Installed artifacts allow only the known same-directory Draco VERSION tool aliases, preserving those and signed target bytes during migration. All test TMP trees are cleaned; logs/receipts and native outputs remain owned and explicit.

Use the frozen exact argv/shell commands supplied in the work handoff. The public stages are:

- `verify-inputs`: validate sealed repository inputs and streaming complete original archive reassembly.
- `prepare`: complete original private extraction, copied actual Blender wrapper inputs, exact patch forward/reverse proof. Requires explicit root, TMPDIR and Git only.
- `plan`: read-only actual compiler/tool version checks, SDK15 `__n1`/15004, Clang20/LLD20, byte-identical SDK15 compiler-rt overlay in the declared Clang20 resource directory; emit native CMake/Ninja commands. Does not configure or compile.
- `full`: prepare, configure/build/install both complete upstream libraries/tools and actual bridge DLLs; run original CMAKE/PC/native DLL gates; audit final installed ELF/PIC/source/metadata; run moved fresh CMAKE/PC and DLL gates. Jobs are restricted to 1 or 2, link pool 1, LLD threads 2.
- `acceptance`, `audit`, `migrate`: rerun distinct native gates in the same exact owned root with `--resume`. Dependent receipts are archived before reruns so failed new runs cannot leave stale aggregate PASS pointers. New migration fixtures use unique run names, and artifact/acceptance/input/prefix hashes must bind together. Individual reruns invalidate the previous full aggregate; their new receipts remain separate.
- `copy-inputs`: copy every sealed input plus the lock into an absent private cache checkout, including complete archives and the actual Blender addon/wrapper baseline. A second full build can then originate from a Unicode/space input root without consulting the old repository. It does not build anything.

All native tools are explicit CLI paths: Python, CMake, Ninja, pkgconf, Git, native Clang20 C/C++, exact `ld.lld` basename, SDK root, resource directory and signer. The builder never mutates those prerequisites. It observes native HarmonyOS/AArch64 and preserves CMake native identity instead of setting Linux, cross status, compiler identities, fake HAVE or probe results. CMake-linked ELF probes, upstream tools, real DLLs and consumers are signed before use; final installed bytes are inspected again for `.codesign`, AArch64, no absolute NEEDED, no RPATH/RUNPATH, no TEXTREL, SDK15 static C++ closure, actual exported C ABI and frozen hashes. The accepted dynamic closure consists of declared native system libraries; consumer executables additionally depend on both real bridge DLLs. A scoped and logged `LD_LIBRARY_PATH=<selected prefix>/lib` is used only for these deliberately metadata-linked consumer processes. Bridge ABI and bpy scripts open the actual resolver paths directly.

The native CMAKE and PC consumers genuinely link both codec libraries and both bridge metadata targets, call bridge C ABI exports, perform indexed position/normal/UV roundtrips, reject corrupt buffers, exercise UTF-8 source codepoints and Unicode/space fixture paths, and dlopen/release real DLL handles. The independent ctypes gate exercises guarded writes, copied input ownership, balanced Draco creation/release, compression filters, attribute/index variants and corruption, then creates correct compressed glTF fixtures. It cannot substitute for actual bpy acceptance.

Installed path namespaces, with execution status recorded separately:

| Relative path below prefix | Purpose |
| --- | --- |
| `lib/libdraco.a`, `lib/libmeshoptimizer.a` | Actual source-built PIC archives |
| `lib/libbf_intern_draco_bridge.so`, `lib/libbf_intern_meshopt_bridge.so` | Actual signed real Blender wrappers, development/native acceptance |
| `share/blender-gltf/host/lib/*.so` | Parent host runtime base `lib` copies; installed during full, host bpy NOTRUN until separate gate |
| `share/blender-gltf/hap/libs/arm64-v8a/*.so` | HAP package namespace copies; actual packaging/install/loader execution NOTRUN |
| `share/blender-gltf/scripts/addons_core/io_scene_gltf2` | Sealed actual addon sources plus DLL copies for a genuine SYSTEM_LIBS resource root |

The unchanged addon loader uses SYSTEM_LIBS plus `scripts/addons_core/io_scene_gltf2/*.so`; when SYSTEM_LIBS is empty it uses `dirname(LOCAL)/lib/*.so`. `BLENDER_SYSTEM_RESOURCES` only changes SYSTEM and cannot redirect SYSTEM_LIBS. Current OHOS GHOST inherits no SYSTEM_LIBS override, so parent portable/HAP runtime staging must provide the actual `dirname(LOCAL)/lib` copies. Adding Python addon search paths alone cannot redirect DLLs. The acceptance scripts compare actual resource paths, loaded source origins and exact native-tested DLL hashes; incorrect staging fails rather than falling back. See `acceptance/README.md` for source locations, precise bpy commands and HAP prerequisites.

For a later safe Blender configuration boundary, the existing formal platform already consumes `draco::draco` and `meshoptimizer::meshoptimizer`; pass the new installed `-Ddraco_DIR=<prefix>/share/cmake/draco`, `-Dmeshoptimizer_DIR=<prefix>/lib/cmake/meshoptimizer`, `-DWITH_DRACO=ON`, `-DWITH_MESHOPTIMIZER=ON`. No current main configuration or formal CMake file is changed by this candidate. Any integration patch remains a separately reviewed candidate. Do not overwrite the running/frozen parents.

The separate real Blender import/export entrypoints require a successfully linked, signed Blender runtime and the native-generated fixture files. They use real `bpy.ops.import_scene.gltf` and `bpy.ops.export_scene.gltf`, assert KHR Draco/EXT meshopt compressed data, geometry bounds, topology/winding, UV seams, normals and material tolerances, decode exported data independently and reimport it. Corrupt Draco is reported with the actual baseline log/result behavior rather than an invented CANCELLED result. The known baseline decoder error-path leak is documented with an unapplied try/finally patch and nine pure-Python cleanup-contract scenarios. Those short contract checks are source evidence only.

Four independent gate states must stay explicit: source/IO candidate verification; native source-built full/bridge acceptance; actual bpy compressed glTF postlink acceptance; and real HAP install/execution acceptance. None implies the next. A frozen source candidate is not a native build PASS or a release-ready runtime.
