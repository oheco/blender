# Source and recipe attribution

The original NumPy 2.3.4 source is BSD-3-Clause. NumPy's complete original `LICENSE.txt`, `LICENSES_bundled.txt` and `.spin/LICENSE` remain in the sealed formal tar inventory; all bundled notices remain unchanged. The actual vendored Meson backend retains its upstream Apache-2.0 files. Cython and all 11 build-tool source entries preserve the exact upstream source/license members recorded in [sources.lock.json](sources.lock.json). The replay installs their original notice bytes, with relative subpaths preserved. SDK static libc++/compiler-rt notices are retained by copying original SDK NOTICE after exact pin verification.

The new replay/signing/acceptance glue is GPL-2.0-or-later, consistent with the existing Blender OHOS recipe namespace. [sign_compiler.py](sign_compiler.py), [module.py](module.py) and [acceptance.py](acceptance.py) are adaptations of the accepted local recipe at `blender-ohos-work/python/hap/numpy`, itself derived from the preceding `blender-ohos-work/python/numpy` native recipe. Original accepted driver, signing compiler and verification source text are retained unchanged in [evidence](evidence/accepted-driver.py.txt); the original signing compiler SHA256 is `b8fd03097d6472c69a006c84ce36c582b499cce9e7322ef08d8f8fbb5f9a6c61`. The new implementation removes absolute old-cache defaults, implicit signer/tool discovery, shell native audits in acceptance, and old-output dependencies; original signed native probe semantics and full math backend are retained.

[The copied NumPy vendored-Meson patch](patches/numpy-vendored-meson-ohos.patch) is **byte-for-byte the original** accepted local OHOS adaptation, SHA256 `22d6830e3151fa567e5a9cea88e914592b20c810abb88a8c3c39704800cb94ca`. It adds honest OHOS system detection and actual relocatable Python `LIBDIR` search. No upstream license/copyright text is removed. [Patch records](patches/patch-record.json) bind exact pristine original tar bytes and exact accepted patched-file bytes; common sourceprep applies and reverses the patch only on owned new copies.

[evidence/accepted-numpy-validation.json](evidence/accepted-numpy-validation.json), [the accepted Python receipt](evidence/accepted-python-validation.json) and [accepted runtime immutability receipt](evidence/accepted-runtime-immutability.json) are read-only historical provenance. The stale accepted configured flag is also preserved truthfully, not interpreted as the latest native build state. These copied files contain their original absolute paths for attribution; replay code never reads or borrows those prefixes. They do not certify this new candidate's native build, runtime execution, Blender behavior, or real HAP install/app policy.
